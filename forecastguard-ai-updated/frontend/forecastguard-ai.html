          Validation methodology

          How this prototype avoids the leakage failure modes common in weather-ML projects.

          • ✓ Temporal train / validation / test split (no shuffling across time)
          • ✓ Bust-label thresholds computed only from training-period years
          • ✓ No verification (ERA5) variables used as model features
          • ✓ No future observations available at prediction time
          • ✓ Isotonic probability calibration on a held-out validation split
          • ✓ Metrics reported on a held-out test split, never seen in training

          Evaluated on a small prototype sample — see the note below the model-performance section for scope.

          Prototype note — this interface is served live by FastAPI over a real WeatherBench2 HRES forecast + ERA5 verification sample (three 2019 initialization dates, 2,430 observations: 810 train / 810 validation / 810 test). Bust probabilities, drivers, and historical analogues all come from the trained, calibrated model — nothing on this page is simulated in the browser except the reliability diagram, which is illustrative pending a dedicated calibration-curve endpoint. Because the sample is small and drawn from a single monsoon week, treat the evaluation numbers below as a prototype signal, not a generalized performance claim — see the technical design for the full production plan (multi-year NCMRWF NWP data, XGBoost with isotonic calibration, SHAP explanations).
